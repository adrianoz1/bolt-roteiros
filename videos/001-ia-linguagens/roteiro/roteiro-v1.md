# Linguagem de Programação ainda importa? 

**Tese:** a IA não escolhe apenas como o código será escrito; ela começa a mudar quais linguagens são economicamente viáveis para uma empresa.  

Talvez a próxima grande linguagem de programação morra antes mesmo de ficar popular.

Não porque ela é ruim.

Não porque ela é lenta.

E nem porque os programadores não gostaram dela.

Mas porque a IA nem mesmo sabe que ela existe. 

De um lado, você tem uma linguagem moderna, segura, com um sistema de tipos absurdamente bem feito e criada para evitar uma quantidade enorme de erros. Do outro, você tem Python: uma linguagem que existe em todo lugar, tem biblioteca para absolutamente tudo e provavelmente já apareceu bilhões de vezes nos dados usados para treinar modelos de IA.

Qual das duas você acha que o agente de IA vai escolher?

Pois é.

Pela primeira vez na história da programação, talvez uma linguagem não precise convencer apenas os programadores a usá-la. Ela também precisa ser boa para os agentes de IA que vão escrever código nela.

E isso muda completamente o jogo.

Até pouco tempo atrás, quando uma linguagem ganhava um recurso novo, o caminho parecia relativamente simples. A documentação era publicada, alguns desenvolvedores começavam a usar, bibliotecas apareciam e, aos poucos, o mercado absorvia aquela novidade.

Agora coloca uma IA no meio desse processo.

Você pede um código em uma versão moderna de Java e ela pode até entregar. Só que existe uma chance enorme de aparecerem padrões antigos, estruturas desnecessárias e aquele cheiro de sistema corporativo que foi criado quando o monitor ainda tinha cinquenta centímetros de profundidade.

Não é porque o modelo odeia Java moderno. É porque ele reconhece padrões a partir do material que recebeu, do contexto que você fornece e das ferramentas que consegue consultar. E linguagens antigas e populares possuem uma vantagem brutal: existe muito código, muita documentação, muita resposta em fórum e muito projeto real disponível.

Uma linguagem nova começa praticamente do zero nessa disputa.

Claro, documentação e contexto podem ajudar bastante. Você pode entregar a especificação inteira para o agente, criar regras no projeto e corrigir o código gerado. Mas isso seria especificamente pra você, não por uma comunidade inteira de desenvolvedores.

E se trazermos para o mundo corporativo, é ainda pior, nenhuma escolhe tecnologia olhando apenas para a beleza do código. Ela olha para prazo, contratação, manutenção, risco e, principalmente, para quanto custa colocar alguma coisa funcionando em produção.

A economia mudou.

Historicamente, o trabalho de escrever código sempre foi caro.

Mas com os modelos de IA atuais, escrever código independente da linguagem de programação ficou muito mais barato. Não ficou automático, não ficou livre de erro e definitivamente não virou trabalho para fazer sem revisão. Mas ficou barato o bastante para mudar a decisão.

Isso significa que programação morreu e todo mundo deveria virar pedreiro?

Ainda Não.

Essa seria justamente a conclusão preguiçosa que um vídeo sobre inteligência artificial não deveria produzir.

Eu mesmo tenho perdido a vontade de produzir conteúdo, porque ninguem mais liga pra código. Pra ser sincero, eu mesmo não abro o editor pra escrever uma linha de código faz meses. E eu me nego ficar trazendo hype aqui pra esse canal de modelos, harness e ferramentas de IA que amanhã vão ter morrido e centenas de outras surgido, são ferramentas de IA sendo criadas por ferramentas de IA, você já percebeu a insanidade disso? 

Mas o meu ponto aqui é outro.

Lembra das antigas disputas entre linguagens de programação?

Então, um agente não sente prazer com uma abstração elegante. Ele não participa de uma comunidade. Ele não tem carinho pela filosofia da linguagem.

Ele altera o arquivo, executa uma ferramenta e precisa receber uma resposta rápida e útil.

No final, a IA não torna a escolha da linguagem irrelevante.

Só que agora não basta perguntar qual linguagem tem a sintaxe mais bonita, o sistema de tipos mais poderoso ou a comunidade mais apaixonada.

Você também precisa perguntar quanto tempo existe entre uma mudança no código e uma evidência confiável de que aquilo funciona.

Porque a linguagem que vai sobreviver à era dos agentes talvez não seja a mais elegante.

Talvez seja a que consegue dizer “isso está errado” antes que a IA tenha tempo de produzir outras dez mil linhas.
